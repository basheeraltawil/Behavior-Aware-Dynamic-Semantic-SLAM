Research Problem

Project Overview

Bridging the gap between geometric mapping and semantic understanding in dynamic environments

🎯 The Challenge

Mobile robots struggle to navigate safely and efficiently in dynamic environments shared with humans. Traditional SLAM systems treat moving objects as noise or obstacles to avoid, lacking understanding of why objects move, how they behave, and what will happen next.

Research Objectives

Develop a novel dual-thread architecture that separates WHERE (localization) from WHAT (scene understanding), enabling robots to:

  • Understand object behaviors and predict future states with high accuracy
  • Generate human-readable scene descriptions and semantic graphs
  • Navigate proactively based on predicted dynamics and social contexts
  • Adapt to complex, human-populated environments in real-time
System Design

Dual-Thread Architecture

Separating localization from understanding for optimal performance and scalability

WHERE Thread (GST)

Geometric SLAM Thread

  • C++ SU-SLAM node `rgbd_node_cpp`
  • Publishes `/slam/pose`
  • Uses optional `/dynamic_ss/semantic_mask`
  • Robot pose tracking (6DOF) with high precision
  • Geometric map management and optimization
  • Real-time performance at 30Hz

WHAT Thread (SUT)

Semantic Understanding Thread

  • Python node `semantic_thread_node.py`
  • Publishes `/semantics/objects`
  • Publishes `/semantics/scene_description`
  • Publishes `/dynamic_ss/semantic_mask`
  • Object detection and classification (YOLO)
  • Behavior analysis and activity recognition

Technical Innovation

YOLO Enhancement for Dynamic SLAM

Leveraging deep learning for robust dynamic object identification and semantic understanding

🚀 YOLO's Contribution to Dynamic SLAM

YOLO (You Only Look Once) object detection transforms ORB-SLAM3 from a static environment SLAM system to a robust dynamic SLAM solution by providing real-time semantic understanding and dynamic object identification. The integration enables precise filtering of dynamic feature points that would otherwise corrupt the SLAM solution.

Mathematical Foundation

Core Dynamic Point Filtering

The fundamental enhancement involves generating a semantic mask that labels image regions containing dynamic objects, constraining ORB-SLAM3 to extract features only from static background regions:

$$I_{\text{static}} = I_{\text{original}} \odot (1 - M_{\text{dynamic}})$$

Where:

  • $I_{\text{original}}$ is the original input image
  • $M_{\text{dynamic}}$ is the binary mask where 1 indicates dynamic object pixels
  • $I_{\text{static}}$ is the resulting image containing only static regions
  • $\odot$ denotes element-wise multiplication

Depth-Assisted Dynamic Point Identification

Your code uses depth values to refine the dynamic object mask. After obtaining bounding boxes from YOLO, the system calculates a representative depth value for the detected object and applies a threshold to segment the precise object region:

$$\text{isDynamic}(x,y) = \begin{cases} 1 & \text{if } |D(x,y) - \mu_{\text{object}}| \leq \tau \\ 0 & \text{otherwise} \end{cases}$$

Where:

  • $D(x,y)$ is the depth at pixel $(x,y)$
  • $\mu_{\text{object}}$ is the representative depth of the detected object
  • $\tau$ is a depth tolerance threshold

Epipolar Geometric Verification

Another approach combines YOLO detections with geometric verification. Feature points within YOLO bounding boxes are verified using multi-view geometry constraints:

$$d(\mathbf{x}', F\mathbf{x}) > \tau_{\text{epipolar}}$$

Where:

  • $\mathbf{x}$ and $\mathbf{x}'$ are matching feature points in consecutive frames
  • $F$ is the fundamental matrix
  • $d(\cdot)$ measures the distance from the point to the epipolar line
  • $\tau_{\text{epipolar}}$ is the epipolar constraint threshold

Points violating this constraint are classified as dynamic.

Confidence-Based Dynamic Filtering

The YOLO detection provides confidence scores that can be integrated into the SLAM optimization:

$$w_i = 1 - \frac{c_i}{\max(c_1, c_2, \ldots, c_n)}$$

Where:

  • $w_i$ is the weight for feature point $i$ in bundle adjustment
  • $c_i$ is the YOLO confidence score for the object containing point $i$
  • Points in high-confidence dynamic regions receive lower weights

Dynamic Object Motion Model

For persistent dynamic objects, we can model their motion to predict future positions:

$$\mathbf{p}_{t+1} = \mathbf{p}_t + \mathbf{v}_t \Delta t + \frac{1}{2}\mathbf{a}_t \Delta t^2 + \boldsymbol{\epsilon}$$

Where:

  • $\mathbf{p}_t$ is the object position at time $t$
  • $\mathbf{v}_t$ is the object velocity
  • $\mathbf{a}_t$ is the object acceleration
  • $\boldsymbol{\epsilon}$ is process noise
  • $\Delta t$ is the time step

Technical Implementation

ROS 2 Integration

Comprehensive guide for converting standalone SU-SLAM into a production-ready ROS 2 package

🚀 Project Overview

We built a ROS 2 package named dynamic_ss that integrates SU-SLAM (enhanced ORB-SLAM3) as a shared C++ library inside colcon/ament, with full support for RGB-D data streams and semantic understanding.

Repository Structure

Standalone SU-SLAM code at SU-SLAM/ containing: - include/, src/, Thirdparty/, Examples/ New ROS 2 package at dynamic_ss/ Key Assets: - Third-party libs: Thirdparty/DBoW2, Thirdparty/g2o, Thirdparty/Sophus - Vocabulary: Vocabulary/ORBvoc.txt.tar.gz (compressed text vocabulary) - YOLO: Thirdparty/YOLO (cfg, weights, labels)

Key Design Decisions

🏗️

Build SU-SLAM as Library

Build SU-SLAM into libsu_slam3.so via CMakeLists.txt inside dynamic_ss package.

📦

Self-Contained Build

Build DBoW2 and g2o from source using add_subdirectory(), not prebuilt .so files.

🗂️

Asset Management

Install ORB vocabulary as plain text and YOLO assets into package share for runtime resolution.

🐍

Python Integration

Python driver for dataset playback and ROS handshake using system Python with NumPy 1.x.

Implementation Steps

1. Package Skeleton Creation

Created dynamic_ss with comprehensive package.xml dependencies and CMakeLists.txt that builds shared library and ROS 2 executables.

2. Third-Party Library Integration

Instead of hard-coded .so paths:

add_subdirectory(../SU-SLAM/Thirdparty/DBoW2 ...)
add_subdirectory(../SU-SLAM/Thirdparty/g2o ...)

This makes the build hermetic under colcon and avoids "No rule to make target" errors.

3. Asset Installation

  • Vocabulary: Extract Vocabulary/ORBvoc.txt.tar.gz during CMake configure
  • YOLO: Install Thirdparty/YOLO to package share
  • Configs: Install Examples/RGB-D/*.yaml to package config directory

4. SU-SLAM ROS 2 Node Wrapper

Node class: RGBDMode uses ament_index_cpp::get_package_share_directory("dynamic_ss") to locate package share.

5. Python RGB-D Driver Node

Parameters: settings_name, association_file, dataset_root

Critical Problems and Solutions

Problem A: C++17 Error - Incrementing a Bool

Error: use of an operand of type 'bool' in 'operator++' is forbidden in C++17 on mnFullBAIdx++

Solution

Change mnFullBAIdx type from bool to int in LoopClosing.h

Problem B: Missing Prebuilt Third-Party .so Files

Error: No rule to make target .../DBoW2/lib/libDBoW2.so

Solution

Build from source using add_subdirectory and link CMake targets; install targets for runtime resolution.

Problem C: Vocabulary Format Mismatch

Error: Vocabulary loading failure: This is not a correct text file!

Solution

Extract ORBvoc.txt in CMake and set default voc_file to installed text file.

Problem D: NumPy 2.x vs cv_bridge ABI Issue

Error: AttributeError: _ARRAY_API not found from cv_bridge

Solution

Switch driver shebang to python3 (system Python) and run with PYTHONNOUSERSITE=1.
